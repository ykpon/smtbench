# smtbench — план реализации


**Цель:** кроссплатформенная (Linux/Windows, amd64) утилита `smtbench`. Она меряет скорость каждого ядра и пары его потоков, пока остальные ядра загружаются «лесенкой», и отправляет результат в Docker-коллектор `smtbench-server` с простым веб-интерфейсом.

**Архитектура:** один Go-модуль, два бинарника.
- **Клиент.** Топология берётся из ОС. Рабочие потоки привязаны к CPU и крутят синтетический «тик» (int/fp/avx/mem). Планировщик окон строит лесенку. Результат — JSON с сырыми точками.
- **Коллектор.** SQLite и HTTP API. Сводку считает общий пакет `summary` из сырых точек. Интерфейс на vanilla JS + uPlot встроен через `go:embed`.

**Стек:** Go 1.26, `golang.org/x/sys` (unix, windows, cpu), `modernc.org/sqlite`, uPlot 1.6.30 (лежит в репозитории), Docker (alpine 3.20).

**Спека:** `docs/specs/2026-11-14-smtbench-design.md` (дальше — «дизайн»). Исполнитель читает её вместе с планом.

## Global Constraints

- Модуль `smtbench`, `go 1.26`. Все бинарники собираются с `CGO_ENABLED=0`. Целевые платформы: `linux/amd64` и `windows/amd64`.
- Зависимости только `golang.org/x/sys` и `modernc.org/sqlite`. Фронтенд без npm и CDN: uPlot лежит в `web/vendor/`.
- Всё, что видит пользователь (сообщения CLI, интерфейс, ошибки API), — на русском. Идентификаторы и комментарии в коде — на английском.
- У всех структур, которые уходят в JSON (`result`, `summary`, `collector.Meta`), теги в snake_case: `ticks_per_sec`, `full_single_pct`, `has_pair` и т.д.
- `result.SchemaVersion = 1`, `kernels.Version = 1`, `summary.Version = 1`.
- Значения по умолчанию в `run`: profile `int`, duration `3s`, warmup `1s`, reps `1`, step `1`, order `near`, bg-threads `2`, modes `single,pair`, noise-max `3`.
- Коллектор по умолчанию: `--listen :8080`, `--db /data/smtbench.db`, `--max-body 32MiB`, `--download-dir /app/download`, без авторизации.
- Утилита не меняет систему: governor, турбо, чужие процессы, модули ядра.
- Режимы окон: `single`, `solo_b`, `pair`, `final`.
- Расстояние между ядрами: 0 — одна группа L3, 1 — один сокет, 2 — разные сокеты.
- Ядро нумеруется по наименьшему номеру своего потока. Поток A ядра — меньший номер, B — второй.
- Тесты локально: `go test ./...` из `C:\Users\eka\smtbench` (Git Bash: `cd /c/Users/eka/smtbench`). Linux-тесты гоняются на `root@test-host:666` через `scripts/remote-test.sh` (задача 1).

## Review Focus

1. **Ctrl+C или SIGTERM посреди прогона.** Вся нагрузка останавливается меньше чем за 1 с. Частичный JSON сохраняется с `partial: true`, код выхода 130. Тесты: задачи 9 и 13.
2. **Коллектор недоступен.** JSON сохраняется до отправки, код выхода 2, печатается готовая команда `smtbench send …`. Тест: задача 13.
3. **Нестандартная топология:** cpuset или контейнер разрешает не все CPU, HT выключен, у ядра разрешён один поток. Такие ядра идут без solo_b и pair, без паники. Тесты: задачи 2 и 8.
4. **`--profile avx` на CPU без AVX.** Ошибка до старта нагрузки, а не SIGILL. Тест: задача 7.
5. **Памяти не хватает на буферы mem** (число потоков × mem-size > доступной памяти). Понятная ошибка с подсказкой `--mem-size` до старта нагрузки. Тест: задача 13.

type Topology struct {
    Vendor, Model string
    CPUs  []CPU      // sorted by ID
    Cores []Core     // sorted by ID (ID = min thread id order index: 0..n-1)
    L3    []L3Group  // ID by min cpu id order
    Packages int
}
type CPU     struct{ ID, Core, Package, NUMA, L3 int }
type Core    struct{ ID, Package, L3 int; Threads []int } // Threads ascending; [0]=A, [1]=B
type L3Group struct{ ID, SizeKB, Package int; Cores []int; Big bool }
type rawCPU  struct{ ID, Package, NUMA int; Siblings, L3CPUs []int; L3SizeKB int }
func build(raw []rawCPU) (*Topology, error)
func ParseSysfs(sys fs.FS) (*Topology, error)        // sys = root of /sys/devices/system
func ParseCPUList(s string) ([]int, error)           // "0-3,8,10-11\n" → [0 1 2 3 8 10 11]
func (t *Topology) Distance(coreA, coreB int) int    // 0/1/2
func (t *Topology) CoreByID(id int) (Core, bool)
func (t *Topology) HasSMT() bool                     // any core with 2 threads
func (t *Topology) Restrict(allowed []int) (*Topology, error) // drop CPUs not in allowed; drop empty cores/groups; keep IDs
func (t *Topology) Info() result.CPUInfo             // Features/FreqSource filled by caller

**Интерфейсы:**
- Consumes: `build`, `rawCPU` из задачи 2. `x86.Brand()` и `x86.Vendor()` — из задачи 5. До задачи 5 Detect заполняет Model и Vendor пустыми строками, в задаче 5 они подключаются.
- Produces:
```go
func ParseGLPIEx(buf []byte) (*Topology, error)
func Detect() (*Topology, error) // linux: ParseSysfs(os.DirFS("/sys/devices/system"))
                                  // windows: GetLogicalProcessorInformationEx(RelationAll=0xFFFF) → ParseGLPIEx
```
`Detect` **не** вызывает `affinity`: иначе получится цикл импортов (`affinity` на Windows использует данные о группах). Вызывающий сам делает `topo.Restrict(allowed)`: CLI в задаче 4, хелпер тестов раннера в задаче 9.
**Разметка** (смещения от начала записи; заголовок записи — `Relationship u32 @0`, `Size u32 @4`, полезная нагрузка с `@8`, следующая запись — `+Size`):
- **RelationProcessorCore = 0** (то же для Package = 3): `Flags u8 @8` (1 = SMT), `GroupCount u16 @30`, массив `GROUP_AFFINITY @32`. Каждый элемент 16 байт: `Mask u64 @0`, `Group u16 @8`.
- **RelationCache = 2:** `Level u8 @8`, `CacheSize u32 @12`, `Type u32 @16`, `GroupCount u16 @38`, массив `GROUP_AFFINITY @40`. Брать `Level == 3`, `Type` = Unified (0) или Data (2).
- **RelationNumaNode = 1:** `NodeNumber u32 @8`, `GroupCount u16 @30`, `GROUP_AFFINITY @32`. Если `GroupCount == 0`, взять одну маску `@32`.
- **Номер CPU** = `Group*64 + bit`.
